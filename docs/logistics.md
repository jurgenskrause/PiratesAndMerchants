# Layer 2 physical logistics

`dist/logistics.js` implements the six-phase merchant lifecycle, with typed declarations in `logistics.d.ts`. `navigation.js` supplies bounded A* routes, full-hull land/depth clearance, wind costs, visibility compression and analytical tack waypoints. All movement is performed by the existing `Ship.step()` with rudder and fixed canvas stages. No position interpolation, artificial thrust or predicted player intent is used.

## Integration

Provide an actual Layer 1 `EconomicEngine`, the native generated world, and explicit port records `{id, owner_faction, position, island_id?, black_market?}`. Port positions must be navigable approach points with hull clearance and enough depth; the rendered dock center is not automatically a suitable berth for every hull. Map faction IDs explicitly: British -> ENGLAND, French -> FRANCE, Spanish -> SPAIN, Pirate -> PIRATES. Preserve the existing faction colors in the renderer.

Pass a real policy implementing `canTrade`, `canEnter`, `isHostile`, and `isFriendly`. Layer 3 has not been implemented and is not replaced with permissive placeholder rules. The host can supply its chosen current rules explicitly. Optional providers expose external threats, storm/reef circles, friendly forts or allied groups, and territorial ownership. Native local wind sampling applies during pathfinding and each physics substep. Update `wind`/`windField` as the existing wind system changes.

Run the economy tick before the logistics tick on the host simulation clock. The logistics tick does not advance Layer 1 itself. Durations must be in (0, 1] seconds; native physics advances in at most 1/60-second substeps, preserving the supplied duration. Scan timers are in seconds, not render frames. Spawn a vessel through `spawnVessel`; ships near a port scan autonomously, while ships spawned away from ports remain idle until given shelter by hazard/fleet operations. Render copied `getAgentState()` snapshots with the existing hull atlases. The sea trial now connects these modules through the merchant traffic worker; see `merchant-traffic.md` for its bounded fleet and temporary market settings.

## Accounting and behavior

- All seven existing hulls map to the required vessel classes; FIRST_RATE uses Man-of-War. No-go angles retain the existing 35–45 degree settings. Tack angles maximize the shared sailing polar's upwind velocity, with clearance above the no-go boundary. Deep-draft AI avoids depth below its draft; the player's all-water movement rule is unchanged.
- Cargo volume is one hold unit per commodity unit. Default capacities come from the existing fleet, including Fluyt 420. Explicit per-agent `max_cargo_capacity` supports other balanced fleets and the specification's 600-unit acceptance fixture. Weapons are not simulated.
- Orders buy through `executeTransaction`, respecting reservations, wallet, hold capacity, identified owners and available units. Cost basis is the actual untaxed payment. Unloading sells the physical manifest through Layer 1 and receives the funded buyer payment. Repeated arrival cannot resell consumed cargo. Prices can change while a ship is sailing.
- Routing uses the supplied risk formula, with untaxed buy/sell prices, actual planned path length and a configurable voyage-cost estimate. Voyage cost is an opportunity estimate, not an additional wallet expense. Initial defaults are wallet 10,000, vessel value 1,000, range 300 world units, cost estimate 0.1 gold per world unit and tolerance 1; these are exposed balancing settings. Opportunity scans occur every 5 seconds by default. A* is limited to 12,000 node expansions; routes that cannot be found within the limit are skipped rather than teleporting. Clearance caching is bounded and assumes terrain remains static; recreate the engine for a regenerated map.
- Threat detection covers every direction within 20 world units by default. Reports expire after 10 seconds and project supplied threat velocity. Hostility comes from policy. A strength above tolerance triggers fleeing, with escape heading chosen by shared polar speed projected **away** from the threat. Replanning is throttled, and the closest reachable friendly harbor, fort or allied group is selected. Hazard circles use the same avoidance path. Navigation looks ahead through turning distance and reduces sail while turning sharply.
- `receiveCargo` accepts an explicit physical transfer from a capture/loot system without changing port stock or gold. The caller must remove these units from their previous owner. Black-market dumping requires physical arrival and a flagged accessible black market. Dumped cargo is explicitly removed from the inventory; it creates neither market stock nor proceeds. `depositCargo` is a separately identified move, not a goods-creation API.
- `processVesselInterdiction` is a Layer 4 hook, not a combat simulation. A nonfatal interception confiscates the manifest and triggers flight; fatal interception also deactivates the vessel. Repeated fatal reports are rejected. No weapons, damage, sinking animation or combat maneuvers are implemented here.
- Micro-trickle applies only to explicit pairs of distinct island IDs within 12 world units. Bidirectional trade permission is required. It transfers at most 0.05 units per second toward stock equality, using new atomic Layer 1 `transferStock`, conserving units and protecting reservations. No merchant wallets or taxes are involved in this local background movement.
- Incident kinds are interdiction, cargo dump and border incursion. External API incidents queue until Phase 6, after arrival/trickle. The host bus receives `ON_LOGISTICS_INCIDENT`; listener failures are returned without undoing committed state. Mutation during dispatch is rejected. Heatmap bins aggregate loss value and interception count; the result normalizes by square miles using `worldUnitsPerMile` (default 1). Seeded threat ratings can be set explicitly. Knots are an arcade display conversion (`knotsPerSpeedUnit`, default 8); native movement retains existing world units per second.

Run `node tests/logistics.test.mjs` and `node tests/economy.test.mjs`. Tests cover all five specified acceptance cases, complete native-physics upwind arrival, obstacles, draft, cargo conservation, revenue/reservation isolation, micro-trickle and Phase 6 loss telemetry.

Ship running costs accrue during elapsed undocked simulation time into funded
sailors and maintenance purses, then settle once at the next dock. Docked cargo
handling does not accrue overhead. See [Phase 1E](ship-running-costs-phase1e.md).
